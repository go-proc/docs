    go-proc documentation¶

    Pure-Go (CGO-free) process-lifecycle primitives — reap, supervise, respawn. A small family of dependency-free Go libraries, extracted and generalized from a microVM init, that answer the three questions any long-running init has to answer: who reaps the orphans, who keeps the workload up, and when should a crash actually restart.

    Status: both primitives shipping

    supervisor provides a PID-1 subreaper and a policy-driven process supervisor; respawn provides the debounce / anti-thrash / backoff decision core and its concurrent reconciler. Both are pure Go with CGO_ENABLED=0, dependency-free, at 100% coverage, and CI-green across the six 64-bit Go targets (amd64, arm64, riscv64, loong64, ppc64le, s390x).

    The two primitives¶

    Module Import path What it does
    supervisor github.com/go-proc/supervisor A subreaper (SIGCHLD + Wait4 on Linux, portable no-op stub elsewhere) that adopts and reaps orphaned children, plus a supervisor that drives a pluggable Runtime over a Spec of Procs and restarts each per its RestartPolicy (Never / OnFailure / Always), correlating every exit back to the process that owns it.
    respawn github.com/go-proc/respawn A restart / reconcile state machine: a pure Decide(policy, history, attempt, signal, now) → Plan core — grace-period debounce (anti-flap), max_restarts sliding-window anti-thrash, constant / exponential backoff — wrapped in a concurrent per-unit Reconciler driven by down / up / unhealthy / healthy signals through a caller-supplied Actions interface.

    The two compose: supervisor owns the OS-level reaping and process running, while respawn owns the decision of whether and when a down process should come back. Either can be used on its own.

    Design in one line¶

    supervisor reaps and runs; respawn decides.

    The restart decision is a pure function of policy and history, so it is tested exhaustively without spawning a single process; the OS-facing reaper is isolated behind build-tagged files with fault-injection seams. See Why these primitives for the full rationale.

    Quick taste¶

    supervisor — become a subreaper and supervise a spec:

    stop := supervisor.StartReaper()   // Linux: PR_SET_CHILD_SUBREAPER + SIGCHLD/Wait4
defer stop()                       // elsewhere: portable no-op

sup := supervisor.New(runtime, supervisor.Spec{
    Procs: []supervisor.Proc{
        {Name: "api", Restart: supervisor.Always},
        {Name: "batch", Restart: supervisor.OnFailure},
    },
})
sup.Run(ctx)                        // starts, watches, restarts per policy

    respawn — decide whether a down unit should restart:

    plan := respawn.Decide(policy, history, attempt, respawn.SignalDown, time.Now())
switch plan.Action {
case respawn.Restart:  // after plan.Delay (backoff)
case respawn.Debounce: // still inside the grace window
case respawn.GiveUp:   // max_restarts exceeded in the window
}

    Principles¶

    • Pure Go, CGO_ENABLED=0 — trivial cross-compilation, a single static binary, no C toolchain. Linux-only syscalls sit behind build tags with a portable no-op stub.
    • Mechanism, not policy engine. Reaping and running are separated from the restart decision; the decision is a pure, exhaustively-testable function.
    • Dependency-free. No third-party imports — only the standard library.
    • 100% test coverage is the target, enforced as a CI gate, error branches included.
