    Why these primitives¶

    Every long-running init or supervisor — a microVM PID 1, a container entrypoint, a service manager — has to answer three separate questions:

    1. Who reaps the orphans? When a process re-parents its children to PID 1 and then those children exit, someone must wait() on them or they become zombies forever.
    2. Who keeps the workload up? When a supervised process exits, someone must notice, correlate the exit to the right workload, and decide whether to run it again.
    3. When should a crash actually restart? Restarting immediately, always is how you get a crash-loop that pins a core. The real answer is a policy: debounce brief flaps, back off, and give up after too many restarts in a window.

    go-proc splits these cleanly. supervisor owns questions 1 and 2 — the OS-facing reaping and the process running. respawn owns question 3 — the decision, as a pure function. The split is the whole point: it lets the tricky, timing-sensitive restart logic be tested exhaustively and deterministically, with no processes and no clock, while the syscall-bound reaper stays small and isolated.

    Reap: the subreaper¶

    On Linux, supervisor.StartReaper() marks the current process as a child subreaper (PR_SET_CHILD_SUBREAPER) and installs a SIGCHLD handler that loops Wait4(-1, …, WNOHANG, …) to harvest every exited child — both the processes it started and the orphans re-parented to it. Exits it recognizes are routed back to the supervisor so the owning Proc learns its child is gone; unknown PIDs (true orphans) are simply reaped and discarded.

    The syscalls are Linux-only, so they live in build-tagged files (*_linux.go) with a portable no-op stub for every other GOOS. That is what lets the package build, test, and reach 100% coverage on macOS and Windows CI lanes while the real reaping is exercised on Linux.

    The reaper is a mechanism. It has no opinion about restarts — it turns OS signals into "process N exited with status S" facts and hands them upward.

    Supervise: driving a spec over a pluggable runtime¶

    supervisor.New(runtime, spec) takes a Spec — a set of named Procs, each with its own RestartPolicy (Never, OnFailure, Always) — and a pluggable Runtime (the thing that actually starts and stops a process). It starts each proc, watches for exits via the reaper, and applies the policy. Because the Runtime is an interface, the same supervisor drives real OS processes in production and a fake, deterministic runtime in tests — no forking required to reach full branch coverage.

    Respawn: the decision is a pure function¶

    The restart policy is deliberately not in supervisor. It is a standalone module, respawn, whose core is one pure function:

    Decide(policy, history, attempt, signal, now) → Plan

    Given the policy, the restart history, the current attempt, the incoming signal (down / up / unhealthy / healthy) and the current time, it returns a Plan: restart now, restart after a backoff Delay, debounce (still inside the grace window), or give up (too many restarts in the sliding window). No I/O, no goroutines, no wall-clock — now is a parameter — so every branch (anti-flap debounce, anti-thrash window, constant vs. exponential backoff) is unit-tested against fixed inputs.

    That pure core is then wrapped in a concurrent, per-unit Reconciler that receives the real signals and calls a caller-supplied Actions interface to carry out the plan. The concurrency and the effects live in the reconciler; the logic lives in Decide, where it can be proven correct.

    Why pure Go matters here¶

    Because both modules are CGO-free and dependency-free, they:

    • cross-compile to every Go target with no C toolchain, and link into a single static binary — exactly what an init that ships inside a microVM image needs;
    • carry no third-party dependencies — only the standard library and, on Linux, golang.org/x/sys-level syscalls behind build tags;
    • reach and hold 100% coverage including error branches, because the OS-facing parts are behind interfaces and stubs and the decision logic is a pure function.

    See supervisor and respawn for the concrete surfaces.
